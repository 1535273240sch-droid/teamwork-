# Teamwork 机制说明 & 与你现有 orchestrate 的关系

这份文档回答两个问题：

1. **Teamwork 到底"强制"了什么？** 哪些是运行时物理拦截的，哪些其实只是写在提示词里、靠 agent 自觉。
2. **它和你已有的 `orchestrate` skill 是什么关系？** 怎么配合，什么时候用哪个。

---

## 一、把"强制"拆开看

"多智能体框架"这个词容易让人以为整个流程都被硬性约束了。**实际上只有一部分是真的强制。**

| 机制 | 谁在执行 | 是不是真强制 |
|---|---|---|
| **文件独占锁** | `PreToolUse` 钩子 | ✅ **真强制**——物理拦截，写不进去 |
| **角色隔离**（独立上下文 + 独立工具权限） | ZCode subagent 运行时 | ✅ **真强制**——Critic/Auditor 拿不到 Edit/Write 权限 |
| **每轮验证 + 自动继续** | Goal Mode | ✅ **真强制**——ZCode 运行时行为，不靠 agent 记性 |
| **只认真实证据** | Goal Mode 的验证器 | ✅ **真强制**——不认计划、不认总结 |
| **宪章跨会话注入** | `SessionStart` 钩子 | ✅ **真强制**——每次新会话自动注入，防跑偏 |
| 规划先行 + 人工批准 | `/teamwork` 命令 + skill | ⚠️ **半强制**——流程规定，但没有机制阻止 agent 提前动手 |
| **做和验分离**（谁做的不许自己验） | 主 agent 的调度 | ❌ **靠自觉** |
| **四个验证问题全覆盖** | 主 agent 的调度 | ❌ **靠自觉** |
| **终审对着宪章而不是里程碑** | success-auditor | ❌ **靠自觉**（但它是流程最后一个角色） |

### 一句话总结

**真被强制的，是"物理动作"和"运行时行为"；靠自觉的，是"该派谁去验"。**

- 文件锁、权限、Goal Mode 验证、宪章注入——**你不配合也躲不掉**
- "派一个没参与实现的 agent 去验"——**这写在 skill 里，但主 agent 可以选择跳过**

**所以：这套框架显著提高了"你被骗的概率"，但没有降到零。** 唯一能降到零的办法是给 `PostToolUse` 加钩子去强制检查"每个里程碑是否有一个非实现者的验证记录"——那需要写额外代码，现在没做。

### 实践建议

用它的时候，**在访谈的"独立验证"那一栏里，把"由谁验"写死**（比如"必须由 critic 或 auditor 验证，且不许是 worker"）。写进宪章之后，Goal Mode 每轮验证时会拿它当标准，**这时候它就从"靠自觉"变成"被检查"了**。

## 二、和 `orchestrate` 的关系

你已有的 `~/.zcode/skills/orchestrate/` 是一套**编排者-工人工作流**，六步：澄清需求 → 方案确认 → 拆分派活 → 逐个审查 → 整合 → 交付。

两者**不是替代关系，是不同层面的东西**。

### 相同的地方

- 都要求**先澄清再动手**（orchestrate 的"澄清需求" = Teamwork 的 Phase 1 访谈）
- 都要求**方案先给人确认**（orchestrate 的"方案确认" = Teamwork 的宪章批准）
- 都讲**拆分、并行、回传纪律、写冲突隔离**
- 都讲**成本意识**（你的 orchestrate 里写着"多智能体比单智能体贵约 90%"）

**说明你已经有一套成熟的多智能体方法论了。** Teamwork 不是来取代它的。

### 关键的区别：审查由谁做

这是两者最本质的分歧。

| | `orchestrate` | `Teamwork` |
|---|---|---|
| **谁审查** | **主 agent 自己**（它是编排者，它审） | **独立的 subagent** |
| **审查分几个角度** | "逐个审查"——一个通用检查 | **四个不同的角色，问四个不同的问题** |
| **审查者能看到什么** | 主 agent 的全部上下文 | 独立上下文，**且不信任实现者的报告** |
| **写冲突** | 靠纪律：worktree / 分支 / 独立子目录 | **靠钩子物理拦截** |
| **目标收敛** | 靠主 agent 循环 | 靠 Goal Mode 每轮自动验证 |

**最关键的一条：`orchestrate` 的审查是主 agent 做的，那本质上还是"同一份判断的第二遍"。**

Teamwork 的 Auditor 是一个**独立上下文、独立工具权限、明确被要求"不信任 Worker 报告"**的 subagent。它会自己重跑一遍，对比数字。

### 具体差在哪——一个例子

一个量化策略回测出高收益：

- **`orchestrate` 的审查**：主 agent 检查代码跑没跑通、对照验收标准看 diff。**它不会去怀疑"这个收益本身是不是真的"。**
- **`Teamwork`**：
  - **Challenger** 专门去查**这收益是不是来自未来函数、是不是在测试集上调参、基线是不是挑了个弱的**
  - **Auditor** 从干净状态重跑，看数字对不对得上
  - **Success Auditor** 问"当初要的是一个能上实盘的策略，还是一个漂亮的回测数字"

**`orchestrate` 不会帮你做这件事，因为它的审查者就是那个建东西的人。**

## 三、怎么配合用

### 实操建议

| 场景 | 用什么 |
|---|---|
| 日常复杂任务、拆分并行、需要多工人协作 | **`orchestrate`**——更轻，你已经用熟了 |
| 结论必须可信、答错代价高、你自己没法一眼验证 | **`/teamwork`**——四个独立验证角色值这个钱 |
| 跨几十个文件的重构 / 迁移 | **`/teamwork`**（Distributed Coding 形态） |
| 量化策略、实验结论、研究报告 | **`/teamwork`**（Challenger 是它最值钱的部分） |
| 单文件修复、小改动、几分钟的事 | **都别用**，直接做 |

### 一句话判断

> **如果这个结论错了、而你没法靠自己一眼看出来，用 `/teamwork`。否则用 `orchestrate`，或者干脆自己做。**

### ⚠️ 一个要注意的地方

**两者是两套独立的流程定义，不会自动叠加。** 主 agent 只会执行它认为你在要的那一个。

- 敲 `/teamwork` → 走 Teamwork 流程
- 说"按 orchestrate 的流程来" → 走 orchestrate 流程
- **不要指望"两个都生效"**——它们的步骤有重叠，同时执行会互相打架

## 四、装了什么、放哪了

本次安装走的是 ZCode 的**用户级目录**（不是插件注册表），因为插件安装要走 App 内部的网络请求，外部没法驱动。

```
~/.zcode/
├── agents/                      ← 8 个角色（中文）
│   ├── sentinel.md              起点关卡
│   ├── orchestrator.md          拆解与依赖图
│   ├── explorer.md              只读调研
│   ├── worker.md                实现
│   ├── critic.md                查实现的缺陷
│   ├── challenger.md            攻击前提
│   ├── auditor.md               独立复现证据
│   └── success-auditor.md       终审
├── skills/teamwork/SKILL.md     Phase 1 访谈
├── commands/teamwork.md         /teamwork
├── hooks/teamwork/
│   ├── ownership-lock.mjs       文件独占锁
│   └── session-context.mjs      宪章注入
└── cli/config.json              ← 钩子注册在这里
```

### 和"插件形式"的区别

| | 现在（用户级目录） | 插件形式 |
|---|---|---|
| 功能 | **完全一样** | 一样 |
| 出现在 Plugins 页面 | ❌ | ✅ |
| 一键开关 | ❌ | ✅ → 需要走 GitHub marketplace |

要改成插件形式、能在界面里开关和分享给别人，需要在 ZCode 里手动加 marketplace（`1535273240sch-droid/teamwork-`），那一步需要 App 内部的网络请求，外部没法代劳。

### 卸载 / 还原

改动前的所有文件都备份在：

```
~/.zcode/_backup-teamwork-install/<时间戳>/
```

里面是 `config.json`、`agents/`、`commands/`、`skills/` 的原样副本。拷回去即可还原。

### 临时关掉文件独占锁

删掉目标项目里的 `.teamwork/campaign.json` 就行——**钩子在无 campaign 时完全空转**，不影响你日常编辑。
